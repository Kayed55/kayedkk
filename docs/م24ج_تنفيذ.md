## 🛑 توقف 0 — قبل التنفيذ: كشف تعارض الدوال القائمة
```sql
SELECT proname, pg_get_function_arguments(oid) AS args, pg_get_function_result(oid) AS returns
FROM pg_proc
WHERE pronamespace='public'::regnamespace
  AND proname IN ('create_template','update_template','_validate_template_sections');
```
**التفسير والقرار:**
- **صفر صفوف (المتوقّع)** — الدوال جديدة تماماً (كانت مؤجّلة من م24-ب). تابِع مباشرةً إلى الخطوة 1 بـ `CREATE OR REPLACE` كما هو.
- **صفوف موجودة بنفس التوقيع بالضبط** (نفس `args` ونفس `returns`) — `CREATE OR REPLACE` سيستبدلها بأمان. تابِع.
- **صفوف موجودة بتوقيع مختلف** (اختلاف أسماء/أنواع المعاملات أو نوع الإرجاع) — ⚠️ **لا تُنفّذ 37 مباشرةً**:
  - اختلاف **نوع الإرجاع** → `CREATE OR REPLACE` يفشل بـ `cannot change return type of existing function`.
  - اختلاف **توقيع المعاملات** → يُنشئ **overload جديداً** بدل الاستبدال → غموض في PostgREST.
  - **الاستراتيجية:** أرسِل لي ناتج الاستعلام، ثم نُسقِط النسخة القديمة صراحةً قبل 37:
    ```sql
    DROP FUNCTION IF EXISTS public.create_template(<التوقيع القديم بالكامل>);
    DROP FUNCTION IF EXISTS public.update_template(<التوقيع القديم بالكامل>);
    DROP FUNCTION IF EXISTS public._validate_template_sections(<التوقيع القديم بالكامل>);
    ```
    (لا نستخدم `CASCADE` — لا تبعيات متوقّعة؛ لو ظهرت تبعية نتوقّف ونراجع.)

### ✅ شرط العبور: تحديد الاستراتيجية (CREATE OR REPLACE مباشرة، أو DROP ثم CREATE) بناءً على الناتج.

## 🛑 توقف 2 — اختبار عقلاني (dry run) — لا كتابة على أي جدول

المُحقّق `_validate_template_sections` قائم بذاته (لا يحتاج جلسة). نختبر منطق التحقّق مباشرةً في SQL Editor
(المالك يملك صلاحية استدعائه رغم `REVOKE` عن anon/authenticated). **لا `INSERT`/`UPDATE` — قراءة نصّ نتيجة فقط.**

**(أ) أوزان أقسام ≠ 100 (section_based) → يجب أن يُرجع رسالة واضحة (ليس NULL):**
```sql
SELECT public._validate_template_sections('section_based', '[
  {"key":"a","type":"critical","title":"قسم أ","weight":60,
   "subsections":[{"key":"a1","title":"فرعي","weight":100,"items":[{"key":"i1","label":"بند"}]}]},
  {"key":"b","type":"non-critical","title":"قسم ب","weight":30,
   "subsections":[{"key":"b1","title":"فرعي","weight":100,"items":[{"key":"i2","label":"بند"}]}]}
]'::jsonb);
-- المتوقّع: «مجموع أوزان الأقسام = 90% (يجب أن يكون 100%)»
```

**(ب) أوزان معايير ≠ 100 (pdf_based_weekly) → رسالة واضحة:**
```sql
SELECT public._validate_template_sections('pdf_based_weekly',
  '[{"id":"c1","name":"معيار","weight":70},{"id":"c2","name":"معيار2","weight":20}]'::jsonb);
-- المتوقّع: «مجموع أوزان المعايير = 90% (يجب أن يكون 100%)»
```

**(ج) بنية سليمة → NULL (لا خطأ) — للتأكد أنه لا يرفض الصحيح:**
```sql
SELECT public._validate_template_sections('pdf_based_weekly',
  '[{"id":"c1","name":"معيار","weight":60},{"id":"c2","name":"معيار2","weight":40}]'::jsonb) IS NULL AS should_be_true;
-- المتوقّع: true
```

**(د) الفروع المحميّة بالجلسة (نوع غير مدعوم / تعديل نموذج مستخدَم) — عبر واجهة التطبيق بجلستك (أدمن)، لا عبر رمز مُنتزَع:**
- من محرّر «section_based» الجديد: احفظ بأوزان ≠ 100 → يجب أن ترفض الواجهة بالرسالة الخادمية (`create_template`).
- حاوِل **تعديل** نموذج `section_based` مرتبط بقسم+دور له تقييمات فعلية → يجب أن يفشل بـ:
  «لا يمكن تعديل نموذج استُخدم في تقييمات — استخدم «نسخ» (copy) لإصدار جديد».
- (يمكن التأكد من وجود مرشّح مناسب مسبقاً:)
  ```sql
  SELECT t.id, t.name, t.department_id, t.job_role,
         EXISTS(SELECT 1 FROM public.evaluations ev JOIN public.users u ON u.id=ev.employee_id
                WHERE u.department_id=t.department_id AND u.job_role IS NOT DISTINCT FROM t.job_role) AS used
  FROM public.evaluation_templates t WHERE t.template_type='section_based' ORDER BY used DESC;
  ```

> **ملاحظة أمان:** لا ننتزع/نستخدم رمز جلسة مستخدم آخر ولا ننتحل هويّته. الفروع الخادمية المحميّة بالجلسة تُختبر بجلستك أنت داخل التطبيق، أو تُترك للاختبار الوظيفي بعد النشر.

### ✅ شرط العبور: (أ)(ب) تُرجعان رسالة صحيحة، (ج) = true، و(د) يفشل التعديل ويقترح النسخ.

## 🛑 توقف 3 — تحقّق REVOKE/GRANT
```sql
SELECT proname, proacl FROM pg_proc
WHERE pronamespace='public'::regnamespace
  AND proname IN ('create_template','update_template','_validate_template_sections');
```
**المتوقّع:**
- `create_template` و`update_template`: `proacl` يتضمّن `anon=X` و`authenticated=X` (منح التنفيذ)، ولا يتضمّن `=X/` عام (PUBLIC).
- `_validate_template_sections`: **لا** منح لـ anon/authenticated (داخلي — `proacl` بلا anon/authenticated، أو NULL يعني المالك فقط بعد الـREVOKE).

### ✅ شرط العبور: المنح مطابقة (RPCان متاحان لـanon+authenticated، والمُحقّق داخلي).
